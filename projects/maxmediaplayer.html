Case study · Solo product, live on the App Store

MaxMediaPlayer

Swift 6 · VideoToolbox · StoreKit 2 · Tuist monorepo · On the App Store ↗

Problem

iOS has no first-class playback for Matroska/WebM files — the containers most high-quality media actually ships in. Existing players wrap decades-old C libraries. I wanted to know whether one engineer could build the whole thing natively: demuxer, streaming engine, store, release pipeline.

Build

The core is a pure-Swift Matroska/WebM (EBML) demuxer written from scratch, feeding a bounded-memory streaming engine — memory-mapped reads pushed straight into Apple's hardware decoders (AV1/HEVC/H.264 via VideoToolbox). Seeking is O(1) via the Cues index, so a 60 GB file starts instantly and scrubs like a local MP4.

The release operation is itself engineered: the entire App Store lifecycle runs through the App Store Connect API as a CI-style pipeline — subscription and IAP creation across 175 territories, localized listings in 5 languages, and review submission. Passed App Review including LGPL-2.1 compliance.

The pure-logic core carries 327 unit tests running on macOS and Linux CI under Swift 6 strict concurrency, inside a Tuist-managed monorepo of ~20 SwiftPM packages. Nine beta builds in three weeks closed out field-reported issues.

Outcomes

  • 175 countries live on the App Store, with localized listings in 5 languages
  • 60 GB files play with instant start and O(1) seeking on hardware decoders
  • 327 tests on the pure-logic core, macOS + Linux CI, Swift 6 strict concurrency
  • 9 builds / 3 weeks beta-cycle turnaround on field-reported issues
