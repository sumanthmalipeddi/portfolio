AharaOS — condition-aware health OS

FastAPI · Supabase · Gemini + Claude · SwiftUI · aharaos.com ↗

Problem

Generic nutrition apps rank food by macros and ignore the thing that matters most: medical conditions. A protocol that's great for one user is actively harmful for another. The system had to treat condition filters as hard gates — applied before any macro ranking — and extract real markers from the lab reports people actually have: messy PDFs.

Build

An AI health platform of 120+ REST endpoints over 40 SQL migrations, with row-level security on all 19 tables. Multimodal LLM extraction pulls 92 markers from lab-report PDFs; nutrition protocols are generated only after condition filters gate the candidate set.

The LLM layer is engineered for failure: Pydantic-schema structured outputs with automatic Gemini→Claude failover — validated during a real provider outage, not a drill — per-user cost caps backed by a DB-driven pricing ledger, and defense-in-depth security (SSRF guard, CSP with nonces, rate limiting) behind 6 CI gates.

Outcomes

  • 120+ endpoints · 40 migrations · RLS on all 19 tables
  • 92 markers extracted per lab report via multimodal LLM parsing
  • Zero downtime through a real LLM-provider outage via automatic failover
  • 6 CI gates enforcing security and correctness on every change
