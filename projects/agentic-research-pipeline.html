Case study · Work at GetMySaas

Agentic research pipeline

Python · MCP (FastMCP) · Grok agents · PostgreSQL · AWS EC2 · S3

Problem

We had 219,021 software vendors and needed each one's profile page on five company-data platforms. That is far too many to do by hand, and plain search gets it wrong in quiet ways: company names collide, domains change, and a wrong link is worse than no link because it passes every row count.

Build

I wrote a custom MCP server in Python (FastMCP over HTTP) that gives an LLM agent exactly three tools: get the next batch, submit results, and check the queue. Behind it sits a Postgres work queue. Claims are time-limited leases, so if an agent dies its vendors simply go back in the queue. Results are append-only and the latest answer per vendor wins.

The agent gets a least-privilege database role. It can claim work and append results, and nothing else: no updates, no deletes, no DDL, no reads outside its own schema. A test proves it. The server also validates every answer before storing it. The URL has to be a real profile URL for that platform and has to come with evidence (a domain or name match). Anything that fails goes back to the agent with the reason.

Each headless Grok session starts fresh and takes 25 vendors. I tried 50 first, and most of the tokens went into re-reading earlier results. Measuring showed that context growth, not the number of searches, was what drove cost. Sessions run with a locked-down tool policy: only the MCP tools and web search, with sub-agents off. The obvious flag for that did not actually work in headless mode, which I only found by measuring. Every session writes its token count and cost to the database, and an hourly alert reports progress, ETA and stalls.

Alongside the agents, the same queue feeds six search APIs, which I compared head to head with per-key yield tracking.

What I learned

An agent's answer is a claim, not a fact. When I fetched the links from the first batch, 20 to 44% of them were wrong. Since then every link is checked by fetching the page itself before anything downstream trusts it.

Outcomes

  • 4,856 agent sessions · 153,304 vendor submissions · 2.2B tokens, with cost tracked per session
  • 95,089 vendors (43.4%) matched to at least one profile, 259,889 links in total
  • 100% of 219,021 vendors searched at least once (403,732 search results)
  • 15,289 vendors got their first link from the second pass alone
