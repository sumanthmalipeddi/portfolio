Case study · Work at GetMySaas

Zero-loss data platform

PostgreSQL · MongoDB · dbt · Airflow (Cosmos) · Docker Compose · Python

Problem

A B2B SaaS startup needed its market intelligence — hundreds of thousands of person and company records across six heterogeneous sources — unified into marts the business could actually act on. The hard constraint: the production MongoDB sits behind a load balancer that kills long-lived cursors, so a naive full read silently drops records mid-stream. In this domain a silently incomplete load is worse than a failed one.

Build

I designed the load path around the failure mode instead of hoping past it: chunked _id pagination with retry (no cursor lives long enough to be killed), landing into staging tables, count-reconciliation gates that refuse to promote a load that doesn't tie out, and an atomic content swap into the live tables — content-swap rather than table rename, because Postgres views bind by OID.

Downstream, a dbt framework transforms the raw layer into golden records: 12+ models across staging/intermediate/marts, 32 schema and custom tests, SCD Type 2 snapshots, and seed-driven configuration — orchestrated by a 9-task Airflow DAG (Cosmos) in a 6-service Docker Compose deployment. Entity resolution scores match candidates across the six sources with a 5-dimension confidence model and keeps 14 columns of source-attribution provenance, so every merged fact can be traced back to where it came from.

The schema is deliberately honest: no synthetic identity keys, and is_deliverable stays FALSE until independently verified. A wrong guess corrupts deduplication silently; a NULL with a status column never lies.

Outcomes

  • 811,548 person records loaded from production with zero record loss
  • 792,816 contact records in the outreach mart · 48,729 companies in the dimension
  • 423,163 products classified against a 166-category taxonomy I own (architect-approved v3.6.0)
  • 10/10 dbt tests passing on the marts · 32 tests across the framework
